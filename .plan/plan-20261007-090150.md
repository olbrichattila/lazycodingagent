# Refactor Form Architecture to Lazarus Visual Designer

## Overview
Currently, the application layout (Toolbars, Main Menu, Panels, Splitters, Status bar, Controls) is constructed purely via code in `uMainWorkspace.pas`, leaving `mainunit.lfm` empty. This prevents developers from visually inspecting, editing, or dropping components onto the form in the Lazarus Form Designer.

This refactoring plan transitions the main workspace from code-instantiated controls to a **Visual Form Designer approach (`mainunit.lfm` / `mainunit.pas`)** while preserving all existing behaviors (detachable windows, dark/light theme switching, mode selection, and agent capabilities).

---

## Architecture & Goals
1. **LFM / Form Designer First**: Define `TForm1` with visual components placed directly in `mainunit.lfm` (Toolbar, Buttons, ComboBoxes, Splitters, Left Navigation Host, Center Chat Host, Right Host, Status Bar, and Main Menu).
2. **Component Separation & Clean Code**:
   - `mainunit.pas`: Hosts the published component declarations for the designer, published event handlers, and binds actions to state and theme engines.
   - Detachable windowing logic (`uDockPanel.pas`) and theme engine (`uTheme.pas`) remain modular.
   - Embedded sub-panels (Nav rail, Chat view) can be visually hosted inside standard LCL containers (`TPanel` / custom controls) declared on `TForm1`.
3. **Cross-Platform & Modern Design Compliance**:
   - Retain custom paint / theme application on startup and theme toggle.
   - Maintain multi-window / detachable panel system across Windows, Linux, and macOS.
4. **Documentation**: Update `README.md` to reflect the visual designer architecture.

---

## Implementation Steps

### Phase 1: Visual Structure in `mainunit.lfm`
Design and construct full declarative LFM hierarchy for `TForm1`:
- `MainMenu1: TMainMenu` (File, View, Window, Workspace, Agent, Help items)
- `pnlToolbar: TPanel` (Align = alTop)
  - `btnNew: TButton` (Align = alLeft)
  - `btnOpen: TButton` (Align = alLeft)
  - `btnSave: TButton` (Align = alLeft)
  - `pnlSpacer: TPanel` (Align = alLeft)
  - `btnResetLayout: TButton` (Align = alLeft)
  - `btnToggleTheme: TButton` (Align = alRight)
  - `cbModel: TComboBox` (Align = alRight, csDropDownList)
  - `cbMode: TComboBox` (Align = alRight, csDropDownList)
- `StatusBar1: TStatusBar` (Align = alBottom)
- `pnlMainContainer: TPanel` (Align = alClient)
  - Left navigation rail host & content host (`pnlNavHost`)
  - `splNav: TSplitter` (Align = alLeft)
  - Right inspector / instructions host (`pnlReservedHost`)
  - `splReserved: TSplitter` (Align = alRight)
  - Center chat host (`pnlChatHost`)

### Phase 2: Refactor `mainunit.pas`
- Convert `TForm1 = class(TForm)` with published component fields matching `mainunit.lfm`.
- Connect published event handlers:
  - Form events (`FormCreate`, `FormDestroy`, `FormResize`)
  - Menu events (`MenuNewClick`, `MenuOpenClick`, `MenuSaveClick`, `MenuToggleThemeClick`, `MenuResetLayoutClick`, etc.)
  - Toolbar events (`BtnNewClick`, `BtnOpenClick`, `CbModeChange`, `CbModelChange`, etc.)
- Instantiate dock panel wrappers (`TDockPanel`), Navigation rail, and Chat views inside the visually designed host panels.
- Wire workspace state management (`TWorkspaceState`) and theming (`uTheme.pas`).

### Phase 3: Clean up & Deprecate Redundant Dynamic Builders
- Remove manual programmatic control creation (`BuildToolbar`, `BuildMenus`, `BuildLayout`) from `uMainWorkspace.pas` or consolidate `uMainWorkspace` logic cleanly into `mainunit.pas`.
- Ensure all detachable window events (`dpaHide`, `dpaDetach`, `dpaAttach`) continue to work seamlessly with the visually designed host panels.

### Phase 4: Verification & Documentation
- Verify unit dependencies and syntax.
- Update `README.md` to document the Form Designer layout, unit hierarchy, and development guidelines.
