# Architecture & Implementation Plan: LazyCodingAgent Core Logic & Navigation Integration

## 1. Overview & Objectives
This plan outlines the architecture and step-by-step implementation for integrating complete, standalone **agentic logic** into **LazyCodingAgent**.
- **Standalone Local Agent**: Operates as an independent desktop application (no Lazarus IDE package/bundle dependency).
- **Navigation Host Tab System**: The views previously contained in tabs on the legacy form (Chat/Agent, Project Explorer, Sessions, Bots/Tools, Diagnostics/Logs, Tasks/Plans) are hosted inside the collapsible/detachable Left Navigation Host (`pnlNavHost`) and driven by the sleek Left Navigation Rail (`pnlNavRailHost`).
- **Dedicated Settings Dialog & Menu**: All configuration (API keys, endpoints, model selection, tool permissions, timeout, temperature) moves to a clean, dedicated Settings dialog accessible via the main menu (`mnuSettings`).
- **Autonomous Agent Loop (ReAct)**: Full multi-turn agent loop supporting `Ask`, `Plan`, and `Agent` modes with OpenAI/Anthropic/OpenRouter-compatible LLM backends and local tool execution (`read_file`, `write_file`, `list_directory`, `search_code`, `run_process`, `diagnostics`, `todo`).

## 3. Module & Unit Breakdown

### A. Core Agent & LLM Engine (`src/agent/` or project root)
1. **`uAgentTypes.pas`**:
   - Role types (`rUser`, `rAssistant`, `rSystem`, `rTool`).
   - Tool definition records (`TToolDef`, `TToolParam`).
   - Tool call records (`TToolCall`: ID, Name, Arguments) and tool results.
   - Message records (`TChatMessage`: Role, Content, ToolCalls, ToolCallId, Timestamp, TokenUsage).
   - Agent execution states (`asIdle`, `asThinking`, `asExecutingTool`, `asAwaitingConfirmation`, `asError`).
2. **`uLlmClient.pas`**:
   - HTTP transport (`fphttpclient` / Synapse / OpenSSL) supporting standard OpenAI-compatible completions API, OpenRouter, Anthropic Claude messages API, and Ollama local endpoints.
   - JSON serialization & deserialization (`fpjson`, `jsonparser`) for chat completions and function tool calling.
   - Async/threaded request handling to keep the LCL UI fluid.
3. **`uAgentTools.pas`**:
   - Local tool registry and executors:
     - `read_file(path, offset, limit)`
     - `write_file(path, content)` & `edit_file(path, target, replacement)`
     - `list_directory(path, recursive)`
     - `search_code(path, query, regex, file_pattern)`
     - `run_process(command, args, working_dir, timeout)`
     - `diagnostics(target_path, build_action)` (calling local `fpc` or `lazbuild` if configured)
     - `todo(action, tasks_json)`
   - Path resolution & security sandboxing (keeping tool execution scoped to selected workspace root).
4. **`uAgentEngine.pas`**:
   - Multi-turn ReAct reasoning loop:
     1. User submits prompt in `wmAsk`, `wmPlan`, or `wmAgent` mode.
     2. Engine injects mode-specific system prompt and tool definitions.
     3. Engine queries LLM.
     4. If LLM replies with text: append to conversation, update UI.
     5. If LLM replies with Tool Calls: execute tools via `uAgentTools`, feed tool outputs back to LLM, and repeat until task completion or step limit reached.
   - Event callbacks for UI: `OnMessageChunk`, `OnToolStart`, `OnToolFinish`, `OnStateChange`, `OnError`.

### B. Settings & Configuration Management
1. **`uAppSettings.pas` / Enhanced `uWorkspaceState.pas`**:
   - API Configuration: Provider (`OpenRouter`, `OpenAI`, `Anthropic`, `Ollama`), API Key, Base URL, Default Model.
   - Generation parameters: Temperature, Max Output Tokens, Max Agent Iterations (default: 25).
   - Local Tool permissions: Auto-approve read tools, confirm destructive write/run tools toggle.
   - Persistence in application configuration INI file.
2. **`frmSettings.pas` / `frmSettings.lfm`**:
   - Visual Form Designer dialog opened from `mnuSettings` or `Settings...`.
   - Modern styled tabbed categories:
     - **Providers & API Keys** (OpenRouter / Ollama / OpenAI / Anthropic).
     - **Model Profiles** (Model Name, Context Limit, Fallback Models).
     - **Agent & Security** (Workspace Root, Tool Execution Permissions, Max Steps).
     - **Appearance** (Theme: Dark / Light / Accent Colors).

### C. Left Navigation Host & Views (Replacing Form Tabs)
1. **Expanded Navigation Items** (`TNavigationItem` in `uAppTypes.pas`):
   - `niHome`: Dashboard, token counts, quick action triggers.
   - `niProjects`: Workspace file tree explorer (with click to open / inspect).
   - `niSessions`: Historical conversation list with load / save / delete session actions.
   - `niBots`: Custom agent prompt profiles and tool toggles.
   - `niTools`: Live tool execution log & terminal output viewer.
   - `niTasks`: Active plan, execution checklist, and todo item manager.
2. **`uNavContentControl` Upgrade**:
   - Embedded sub-views or stacked panels for each navigation category.
   - File Tree View with double-click handling.
   - Session manager list linked to active chat history.

### D. Chat & Agent Workspace (`uChatPanel.pas` & `mainunit.pas`)
1. **Rich Stream View & Tool Badges**:
   - Display structured message stream with visual cards for tool invocations (e.g., `[Tool: read_file('mainunit.pas')] -> OK (240 lines)`).
   - Mode switcher dropdown (`Ask`, `Plan`, `Agent`).
   - Model switcher combo box populated from active provider config.
   - Cancel / Stop button during active agent loops.
2. **Main Form Menu & Detachables**:
   - Add top-level `mnuSettings` (`mnuSettingsOptions`, `mnuSettingsProviders`).
   - Update `mnuAgent` with `Run Next Step`, `Cancel Agent Run`, `Clear Session History`.
   - Retain full detachable multi-monitor docking support for navigation, chat, context, and utility panels.

## 4. Implementation Steps

### Phase 1: Data Structures & LLM Client
- [ ] Define `uAgentTypes.pas` with messages, tool definitions, tool calls, and state enums.
- [ ] Implement `uLlmClient.pas` supporting OpenRouter/OpenAI/Ollama REST APIs with JSON payload builders and parsers.
- [ ] Unit test HTTP calls and JSON responses across Windows/Linux/macOS targets.

### Phase 2: Tool Registry & Execution Engine
- [ ] Implement `uAgentTools.pas` providing safe local file operations, directory scanning, code searching, process execution, and todo list management.
- [ ] Build `uAgentEngine.pas` implementing the autonomous ReAct execution loop with thread-safe UI callbacks.

### Phase 3: Dedicated Settings Dialog & Workspace State
- [ ] Design visual settings dialog `frmSettings.pas` / `frmSettings.lfm` with dark/light theming.
- [ ] Expand `uWorkspaceState.pas` to persist API credentials, active provider, model lists, and security policies to INI.
- [ ] Wire `mnuSettings` in `mainunit.lfm` and `mainunit.pas`.

### Phase 4: Left Navigation Host Multi-View Integration
- [ ] Update `uAppTypes.pas` with full navigation view definitions (`niHome`, `niProjects`, `niSessions`, `niBots`, `niTools`, `niTasks`).
- [ ] Update `uNavigationPanel.pas` to render all views inside `pnlNavHost` replacing the legacy form tabs.
- [ ] Add interactive workspace file tree and session switching.

### Phase 5: Chat UI & Real-Time Agent Stream
- [ ] Update `uChatPanel.pas` to render real-time streaming tokens, user messages, assistant responses, and collapsible tool execution cards.
- [ ] Add Run/Stop agent controls and model selection synchronization.
- [ ] Connect `mainunit.pas` handlers to start agent sessions and report status in `StatusBar1`.

### Phase 6: Documentation & Testing
- [ ] Update `README.md` with complete documentation of the new agent engine, tool capabilities, navigation host views, and settings configuration.
- [ ] Test cross-platform compatibility, theme switching, multi-monitor detaching, and agent tool execution.

## 5. Verification & Acceptance Criteria
- **Standalone Local Agent**: Builds with `lazbuild lazycodingagent.lpi` without any external Lazarus IDE package dependencies.
- **Nav Host Integration**: All workspace tools, file trees, session history, and diagnostics operate within the left navigation panel.
- **Settings Menu**: Clicking `Settings` opens the dedicated settings form and persists API keys/models cleanly.
- **Agent Autopilot**: In `Agent` mode, the engine autonomously inspects files, runs tools, and delivers completed code edits.
- **Theme & Detachability**: Dark/light mode styling and multi-monitor window detachment remain fully functional.
