# Refactor `uAgentTools.pas` into Modular Single-Tool Units with Factory/Registry

## Overview
Currently, `uAgentTools.pas` contains all tool execution logic (file reading/writing, directory listing, code search, process execution, diagnostics, todo list) in a single file (~670 lines).
This plan outlines decomposing each tool into its own dedicated unit with a clear base class / interface, and restructuring `uAgentTools.pas` as a central tool factory / registry that aggregates and executes the individual tools, adhering to single-responsibility (SRP) and DRY principles while maintaining full backward compatibility with `uAgentEngine`, `mainunit`, and `lazycodingagent.lpi`.

---

## Architectural Design

### 1. Base Tool Class / Contract
Create a base class (e.g. `TAgentToolBase` or `TBaseAgentTool`) in a dedicated unit `uAgentToolBase.pas` (or `uAgentTools.pas`):
- Properties/Fields:
  - `Context: TAgentToolContext`
  - `Name: string` (virtual / abstract property or method)
  - `Description: string` (virtual / abstract)
- Methods:
  - `function GetDefinition: TToolDef; virtual; abstract;`
  - `function Execute(const Args: TJSONObject): TToolExecutionResult; virtual; abstract;`

### 2. Dedicated Units for Each Tool
Each tool will reside in its own unit under the project:
1. **`uToolReadFile.pas`** (`TToolReadFile`)
   - Implements `read_file` tool.
   - Handles path resolution, line range offset/limit, text slicing, and formatted line number output.
2. **`uToolWriteFile.pas`** (`TToolWriteFile`)
   - Implements `write_file` tool.
   - Handles auto-directory creation and atomic/complete file content writing.
3. **`uToolListDirectory.pas`** (`TToolListDirectory`)
   - Implements `list_directory` tool.
   - Handles directory traversal, hidden file filtering, formatting size & type.
4. **`uToolSearchCode.pas`** (`TToolSearchCode`)
   - Implements `search_code` tool.
   - Handles recursive scanning, exclusion of build/git folders, case sensitivity, regex/string matching.
5. **`uToolRunProcess.pas`** (`TToolRunProcess`)
   - Implements `run_process` tool (and alias `shell`).
   - Cross-platform process execution with pipe redirection and timeout tracking.
6. **`uToolDiagnostics.pas`** (`TToolDiagnostics`)
   - Implements `diagnostics` tool.
   - Invokes `lazbuild` / `fpc` against `.lpi`/`.lpr` targets via process runner.
7. **`uToolTodo.pas`** (`TToolTodo`)
   - Implements `todo` tool.
   - Reads / updates session checklist tasks in `TAgentToolContext`.

### 3. Tool Context & Shared Types
- `TToolExecutionResult` remains defined in `uAgentTools.pas` (or `uAgentToolBase.pas` re-exported) to avoid breaking existing callers (`mainunit.pas`, `uAgentEngine.pas`).
- `TAgentToolContext` remains in `uAgentTools.pas` or `uAgentToolBase.pas`, accessible to all individual tool instances.

### 4. `uAgentTools.pas` as Factory & Registry
- Refactor `TAgentToolRegistry`:
  - Maintains an internal list or dictionary/map of instantiated `TAgentToolBase` instances.
  - Implements factory method / initialization where each tool class is registered and instantiated with `FContext`.
  - `GetToolDefinitions`: Iterates registered tools and queries `GetDefinition` for each.
  - `ExecuteTool(const AName, AArgumentsJson: string)`: Parses JSON args, finds matching tool instance by name (case-insensitive), and delegates execution to `Tool.Execute(Args)`.
  - Cleans up tool instances in `Destroy`.
- Public API of `TAgentToolRegistry` and `TAgentToolContext` remains identical, preserving seamless integration with `TAgentEngine`.

### 5. Project File Updates
- Add the new units to `lazycodingagent.lpi` under `<Units>`:
  - `uAgentToolBase.pas`
  - `uToolReadFile.pas`
  - `uToolWriteFile.pas`
  - `uToolListDirectory.pas`
  - `uToolSearchCode.pas`
  - `uToolRunProcess.pas`
  - `uToolDiagnostics.pas`
  - `uToolTodo.pas`

## Detailed Step-by-Step Implementation Steps

### Step 1: Create `uAgentToolBase.pas`
- Define `TToolExecutionResult` (or keep in `uAgentTools` and import).
- Define `TAgentToolContext` (or keep shared).
- Define abstract base class `TAgentTool`:
  ```pascal
  TAgentTool = class
  protected
    FContext: TAgentToolContext;
  public
    constructor Create(AContext: TAgentToolContext); virtual;
    function GetDefinition: TToolDef; virtual; abstract;
    function Execute(const Args: TJSONObject): TToolExecutionResult; virtual; abstract;
    function MatchesName(const AName: string): Boolean; virtual;
  end;
  ```

### Step 2: Implement Individual Tool Units
- **`uToolReadFile.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolReadFile` logic and definition.
- **`uToolWriteFile.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolWriteFile` logic and definition.
- **`uToolListDirectory.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolListDirectory` logic and definition.
- **`uToolSearchCode.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolSearchCode` logic and definition.
- **`uToolRunProcess.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolRunProcess` logic and definition. Handles both `run_process` and `shell` in `MatchesName`.
- **`uToolDiagnostics.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolDiagnostics` logic and definition; leverages `uToolRunProcess` or runner helper.
- **`uToolTodo.pas`**:
  - Subclasses `TAgentTool`.
  - Moves `ToolTodo` logic and definition.

### Step 3: Refactor `uAgentTools.pas`
- `uses` all tool units: `uAgentToolBase, uToolReadFile, uToolWriteFile, uToolListDirectory, uToolSearchCode, uToolRunProcess, uToolDiagnostics, uToolTodo`.
- `TAgentToolRegistry`:
  - Holds `FTools: array of TAgentTool` (or `TFPList` / `TObjectList`).
  - In `Create(AContext)`:
    - Instantiates each tool and adds to `FTools` list (Factory pattern).
  - In `Destroy`:
    - Iterates and frees all tool instances.
  - In `GetToolDefinitions`:
    - Builds `TToolDefArray` by aggregating `GetDefinition` from each tool.
  - In `ExecuteTool`:
    - Parses arguments JSON safely.
    - Finds tool where `Tool.MatchesName(AName)` is true.
    - Executes and returns `TToolExecutionResult`.

### Step 4: Update Lazarus Project File (`lazycodingagent.lpi`)
- Register the new units into `lazycodingagent.lpi` so Lazarus IDE and `lazbuild` track them properly.

### Step 5: Update `README.md`
- As required by project rules, update `README.md` to reflect the modular tool architecture and registry structure.
